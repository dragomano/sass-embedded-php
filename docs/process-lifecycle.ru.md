# Жизненный цикл embedded-процесса

`EmbeddedCompiler` запускает Dart Sass лениво и переиспользует один дочерний процесс `sass --embedded` для всех компиляций, выполненных одним экземпляром компилятора.

## Восстановление

Перед повторным использованием компилятор проверяет, что дочерний процесс ещё работает. Завершившийся процесс удаляется и перезапускается до записи следующего запроса. Если принадлежащий компилятору процесс завершается во время обмена данными, компилятор закрывает его, запускает новый, повторяет handshake и один раз повторяет компиляцию.

Повторяются только транспортные ошибки: broken pipe, EOF и неожиданное завершение процесса. Ошибки Sass, timeout, повреждённые сообщения протокола, несовпадающий compilation ID и несовместимая версия протокола не повторяются.

## Завершение

Когда компилятор больше не нужен, следует вызвать `close()`. Метод идемпотентен: сначала закрывает stdin, чтобы Dart Sass самостоятельно завершился по EOF, дочитывает оставшийся вывод во время ожидания и вызывает `proc_terminate()` только в том случае, если процесс не завершился за отведённое время. Destructor также вызывает `close()` как резервный механизм.

Long-running приложениям следует явно закрывать компилятор при остановке worker, а не полагаться только на сборщик мусора.

## FPM и long-running workers

Ускорение появляется, когда один экземпляр `EmbeddedCompiler` выполняет несколько компиляций. Обычный PHP-FPM не сохраняет объект между запросами, поэтому переиспользования процесса между запросами нет. Несколько компиляций внутри одного запроса всё равно получают выигрыш.

RoadRunner, Swoole, ReactPHP, обработчики очередей и другие long-running workers могут сохранять один компилятор между задачами. Его необходимо закрывать при остановке worker и не использовать один экземпляр для параллельных компиляций.
