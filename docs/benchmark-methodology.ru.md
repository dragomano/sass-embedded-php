# Методика benchmark

Benchmark сравнивает CLI-реализацию `Compiler`, долгоживущий `EmbeddedCompiler` и `scssphp/scssphp`, не меняя их публичные API.

## Сценарии

Каждый выбранный fixture компилируется через `compileString()` и `compileFile()` в двух режимах:

- **cold** создаёт и закрывает компилятор для каждой операции;
- **warm** повторно использует один экземпляр компилятора в течение всего сценария.

По умолчанию используются профили small (25 классов и 2 уровня вложенности), medium (100 классов и 3 уровня) и large (400 классов и 4 уровня). Сгенерированные fixtures кешируются в файлах `generated-<profile>.scss`; параметр `--regenerate` создаёт их заново.

## Проверка корректности

До начала измерений результаты CLI и embedded Dart Sass должны полностью совпадать. Каждый компилятор также должен сформировать непустой результат при компиляции файла. Во время сценария hash результата должен оставаться стабильным для всех измеряемых операций.

Результат `scssphp` не обязан побайтово совпадать с Dart Sass, поскольку форматирование и детали реализаций могут различаться.

## Измерения

В отчёт записываются среднее время одной операции, медиана, p95, пропускная способность, размер CSS и изменение пикового потребления памяти PHP. Память дочернего процесса Dart Sass в показатель PHP memory не входит.

Прогревочные операции не учитываются во времени. Каждый измеряемый запуск выполняет настраиваемое количество операций, после чего продолжительность нормализуется до одной компиляции.

## Воспроизведение

```bash
composer benchmark
php benchmark.php --runs=10 --warmup=2 --batch=3
php benchmark.php --profile=large --input=string
```

Отчёт содержит версии PHP, Dart Sass и scssphp, ОС и архитектуру, размеры и SHA-256 fixtures, а также параметры запуска.
